# SNHUDriverPassSystemDesign
This repo showcases CS 255, a course I took at SNHU that covers business requirements and different system design diagrams.

DriverPass is a client of ours that wants to develop a program that allows users to be able to enhance their driving capabilities through lessons and practice. The owner of the DriverPass, Liam, wanted this program to be run off the cloud based system and for him and his IT officer to monitor it. I feel like I did capture all the requirements he wanted to implement in his program with the diagrams. The business requirements document is one that I would like to return to revise because there are areas where they could be specified more, and the use cases that I went over after could also be used to revise it. From the conversation we had with Liam and his sketch on what he wants his program to look like, I was able to analyze many use cases and design diagrams that reflect their roles.

Use cases are important for system design because it is what the client wants first and most importantly. In addition, the user's needs can be treated as different points of view that make a more functional program. For example there was a use case for resetting passwords. Now many people are capable enough to remember their login information, but for the portion who aren't, we give them a plan b. This way all who use the program have equal opportunity to use it and creates a friendly environment. For future programs and projects, one practice would be to create a Gantt chart (as we did in the beginning of the course) and create a strict schedule for it.
